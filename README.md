# 七圣召唤 · 卡牌与牌组浏览器

纯前端单页应用：牌组分享码解析与生成、卡库浏览与多维筛选、卡库内检索（中文 / 拼音 / 描述，先筛选后检索的两阶段流程）、概念词典与逐层下钻、角色技能（含被动与准备技能、元素骰 + 充能费用）、牌间依赖与构筑校验、多牌组管理、多卡横向对比与两套牌组的差异分析、相似卡替换建议、抽牌概率与费用曲线。

无运行时框架、无打包器依赖；Node 仅用于构建数据与跑回归测试。

## 快速开始

| 方式 | 入口 | 说明 |
| --- | --- | --- |
| 离线单文件（推荐分享） | `dist/七圣召唤-卡牌与牌组浏览器.html` | 约 3.1 MB，样式 / 脚本 / 数据快照与压缩数据集全部内联，双击即开、断网可用 |
| 轻量单文件 | `dist/七圣召唤-卡牌与牌组浏览器-轻量.html` | 约 960 KB，不内嵌原始数据，首次打开联网拉取并缓存 24 小时；压缩数据集仍内联 |
| 多文件开发版 | 根目录 `deck-viewer.html` | 加载构建产物 `dist/app.js`（TypeScript 源码经 esbuild 打包），便于调试 |

开发版需先构建一次脚本（源码已迁到 TypeScript，浏览器不能直接执行 `.ts`）：

```powershell
npm install          # 首次
npm run build:app    # 改完源码后重新打包
```

再通过本地静态服务器打开（`file://` 下现网数据请求可能受浏览器限制）：

```powershell
python -m http.server 8080
# 打开 http://localhost:8080/deck-viewer.html
```

## 移动端

- **浮层不互相遮挡**：≤760px 时对比栏贴边显示、卡名横向滑动；牌组面板会自动抬到对比栏上方，两层浮层不会叠在一起。
- **触控目标**：卡片对比钮、对比表移除钮、弹层顶栏按钮在触屏上放大到 32–38px；触屏点按不再残留 hover 位移与金色高亮。
- **输入体验**：分享码输入框与筛选下拉在触屏上统一 16px，避免 iOS 聚焦时放大整页；分享码输入关闭自动大写/纠错，回车键直接对比。
- **小屏空间**：≤420px 压缩弹层留白与卡图，对比表字段列收窄；弹层高度使用 `dvh`，地址栏收起或键盘弹出时内容不被裁切；对比表与卡名列表支持惯性横向滚动。

## 卡库分组与牌组构筑

- **默认只列可构筑的牌**：卡库按「有没有分享 id」分成两组，默认只渲染可构筑的那组；对局中生成的实体（状态 / 队伍状态 / 召唤物 / 附加状态）与历史版本变体收进底部的「对局实体与历史变体」折叠分组，点标题展开（展开状态记在本地，瓦片按页追加）。若筛选后一张可构筑的都不剩（例如只看「状态牌」），分组会自动展开，不会得到空白页。
- **检索结果同样折叠**：命中里的不可构筑条目单列在同一分组，默认收起，不稀释「找构筑组件」的结果。
- **同名卡 2 张**：除秘传牌（整套限 1 张）外，同名卡最多 2 张。上限只在 `80-deck.js` 的 `copyLimit()` 定义一次，卡库瓦片显示「×1 / ×2」，详情主按钮在已加入 1 张时变成「再加一张 1/2」，加满后禁用并保留「移出」。
- **双计数 + 全局开关**：类别 chip 上的数字是「可构筑 / 不可构筑」（如「队伍状态 0/234」「装备牌 269/19」），整类没有可构筑牌时前半段压暗；排序右侧的「显示不可构筑」开关把不可构筑项直接平铺进来（偏好记在本地），此时不再渲染折叠分组，计数行改为「共 1480 张（可构筑 629 · 不可构筑 851）」。开关状态会编进 `#b=...u=1` 分享链接，收到链接的人看到的是同一屏；但链接只改当前视图，不会覆盖本机默认偏好。
- **牌组摘要只属于卡面视图**：切到卡库 / 列表时自动收起，不会整块压在标签栏上方。

## 性能与内存

卡库一次要面对 1480 条记录，早期版本把结果一次性铺进 DOM，代价是近两万节点、六百多张已解码卡面，滚动时每帧都要参与样式与合成，筛选一次还要重排 1480 条三次。

- **筛选结果 / 分面计数 / 分组拆分按「筛选状态 + 卡池版本」记忆**（`_browseMemo`）：滚动追加、计数刷新、翻页上下文、加牌后的徽标同步都复用同一份，滚动路径上零重算。数据刷新重建卡池时 `poolVersion` 自增，缓存自动失效。
- **分页网格 + 视口外卸载**（`makePager` / `pagerSweep`）：每页 40 张，滚离视口超过 4 页就把该页清空、只留等高占位（滚动条与滚动位置不动），滚回来再挂载。窗口按「页索引」算而不是像素——手机上一页能铺 4000px，用像素阈值会永远不卸载。
- **IntersectionObserver 驱动补页，分帧插入**：不再在 `scroll` 里反复测量布局；首屏同帧补 2 页，之后每帧补 1 页，一次插 100 多张瓦片的长任务被摊开。
- **卡面预留比例**（420×720 写进 `width`/`height` 与 `aspect-ratio`）：图片到达前就占好位，加载完成不再把下方内容顶一次。
- **触屏禁用位移/缩放悬停效果**：不留合成层，滑动更稳。
- **卡壳不额外发请求**：状态图标只出现在不可构筑条目上——默认视图（折叠态）零请求，只有展开分组或打开「显示不可构筑」才加载，每页最多 40 个、单张约 7KB、去重后 182 张命中缓存。

实测（Edge，1440×950 / 390×844，滚动 90 次到底）：滚动帧 p95 从 33.4ms 降到 16.8ms，超过 32ms 的帧从 30~43 个降到 1~12 个，50ms 级长任务消失；DOM 节点从 17.9k 降到 7.8~11k，DOM 内瓦片从 648 张降到 208 张，堆占用 7MB → 6MB。

## 对比与差异

- **多卡对比**：卡库 / 检索结果 / 牌组卡块右上角的「⇄」把卡加入对比，最多 4 张，底部浮动栏汇总已选卡牌。已选 2 张及以上时，详情顶栏也会出现「⇄ n」入口，从详情打开对比、返回后仍停在原卡。点「对比」打开字段表，差异字段以金色标记，可切换「仅看差异」，该偏好会被记住；表头卡名仍可点开详情，返回时回到对比面板，面板的滚动位置也会保留。对比选择只存在内存中，刷新即清空。
- **牌组差异**：顶部「更多 → 牌组对比」，粘贴两套分享码（或点「用当前」填入正在查看的牌组），按 Enter 直接对比；「⇅」交换 A/B，「清空」重置输入。修改分享码后会提示「已修改」，避免把旧结果当成最新。角色按名字匹配，行动牌按 id 汇总，输出新增 / 移除 / 数量变化，并排对比费用曲线与类型分布；可切换是否显示相同的卡。关闭面板再打开，输入与结果仍在。
- **相似卡替换**：对比面板顶栏的「相似卡」展开替换建议。行动牌要求同类型，再按同费用、同关联角色、标签重合排序；角色牌按同元素与标签重合。候选可直接「⇄ 换入」替换当前对比位，也可点名字查看详情后返回对比。

## 抽牌概率与费用曲线

牌组概览里的「抽牌概率与费用曲线」或「更多 → 抽牌概率」打开面板：

- **费用曲线**：0~5+ 元素骰费用的张数与占比，附平均费用与类型分布。
- **关键牌抽牌概率**：任选一张行动牌，按超几何分布给出起手 5 张、第 1~4 回合后（每回合 +2 张）至少 1 张 / 至少 2 张的概率与期望张数。关键牌下拉按类型分组，面板顶部单独高亮起手与第 1 回合的命中概率。不含调度与额外抽牌效果，角色牌不参与行动牌抽牌。

## 发布为在线链接

发布目录固定为 `site/`，入口固定是 `site/index.html`——这样链接不会因为产物名带中文而变长，重发也永远落在同一个应用上（链接不变，内容替换）。

```powershell
# 生成发布用的目录（内置数据快照版，断网也能用）
node scripts/build-single.mjs --out=site/index.html
```

改动后要同步线上：重跑上面这条命令，再对 `D:/Administrator/桌面/data/site` 重新发布即可，不需要改任何发布参数。

为什么发布的是「内置数据快照」版而不是轻量版：单文件版把三份数据内嵌进 HTML，打开即用、不依赖官方接口的跨域策略；线上只多一个卡面图的 HTTPS 依赖（`static-data.piovium.org`），没有后端、没有数据库，静态托管就够。轻量版仍留给「想用最新数据、且接受首次联网 2MB」的场景（本地打开用）。

## 数据模型

分类与身份只在 `src/12-model.js` 定义一处，其他模块（卡池、检索、概念、详情、对比、导出）都只读这一层。此前这三件事分散在 `TYPE_ZH` 表、各视图的 `if` 判断和概念索引的多处启发式里，同一张牌在不同界面可能得到不同结论。

**统一数据集（`scripts/build-dataset.mjs` → `gi-data/dataset.br`）**：四份异构来源在构建期归一为同一种 Record（`key / kind / domain / name / aliases / desc{effect,story,rules} / linkable / art{hasFace,ref} / stats / rel / flags / refs`）。准备状态影子、牌面文本镜像、可构筑、可链接、出边引用都在构建期判定一次，运行时（`src/07-dataset.js`）只读。这样做的直接结果：

- **装备牌赋予的特技进入索引**：`entities.json` 里有 22 张装备牌自带 `skills`（跃升、鲨鲨冲浪板、转转冲击…）。过去技能索引只遍历角色，这些名字在卡文「特技：X」里出现却点不动；现在它们与角色技能同一套索引、同一套检索、同一个技能页。
- **角色简介不再被链接**：`storyText` 是叙事文本，只作为 `desc.story` 存储，不参与 `linkify` 与反链；卡牌效果、技能效果、规则原文才是 `linkable` 文本。
- **牌面统一**：所有界面（卡库、详情、概念页、技能页、对比表头）都走同一个牌面组件，同比例 420:720、同占位、同降级；技能页用所属角色 / 卡牌的牌面作为视觉锚点。

数据集同时输出 `dataset.json`（调试 / 单文件内联 / Node 测试兜底）、`dataset.gz`（gzip，浏览器原生 `DecompressionStream` 主路径）与 `dataset.br`（Brotli，体积更小，供 Node / 归档 / 未来解码器）。三份由同一份记录生成，测试会校验记录数一致。设计与迁移细节见 `docs/DESIGN.md`。

**类型 → 域**（`TYPE_SPEC`）：

| 原始类型 | 展示类型 | 域 | 可进牌组 |
| --- | --- | --- | --- |
| `GCG_CARD_CHARACTER` | 角色牌 | char | 是 |
| `GCG_CARD_MODIFY` | 装备牌 | card | 是 |
| `GCG_CARD_ASSIST` | 支援牌（场地 / 伙伴 / 道具由标签标出） | card | 是 |
| `GCG_CARD_EVENT` | 事件牌 | card | 是 |
| `GCG_CARD_STATE` | 状态牌（挂在角色上） | field | 否 |
| `GCG_CARD_ONSTAGE` | 队伍状态（作用于整支队伍） | field | 否 |
| `GCG_CARD_SUMMON` | 召唤物 | field | 否 |
| `GCG_CARD_ATTACHMENT` | 附加状态 | field | 否 |

`field` 是对局中生成或附着的实体，永远不可构筑；界面上标为「实体」，且不显示「加入牌组」。

**两类"影子"关系**，由数据形态判定一次，不再逐处猜测：

- **准备状态影子**：部分"需准备"的技能在数据里带一个同名 `GCG_CARD_STATE`，描述固定为「本角色将在下次行动时，直接使用技能：X」。它只是技能的运行时标记，因此不进卡池、不占概念名；技能页里以「准备中状态」入口保留。
- **牌面文本镜像**：关键词表里把某张牌的牌面文本原样再存一份（`descMirrors` 判定），它不是独立概念，检索不再单列。

**技能是一等实体**（`src/47-skills.js`）：技能挂在 `characters[].skills` 下，既没有卡面也没有分享码 id。现在为它建立独立索引（key = 角色 id + 技能 id），因此：

- 角色详情列出**全部**技能（含被动与准备技能），不再按 `hidden` 过滤丢掉信息；
- 每个技能行显示费用：元素骰 + 充能（数据源里都在 `playCost`）；
- 技能名进入概念索引（kind = `skill`），卡文里的「准备技能：踏潮」点击即到技能页；同名时卡牌/角色身份优先，规则术语先于技能并列；
- 同一角色下的同名技能只出一条（取描述最完整的一条），阶段数记在 `altCount`。

**展示去重**：

- 卡池按 id 全列（含历史版本变体），不可构筑的区分「实体」与「变体」；
- 「被引用」chips 按显示名合并同名多版本，代表条目优先取可构筑版本，`title` 注明同名条目数；
- 检索按名字归一化去重（`nameKey`：抹平引号、感叹号、加号与空白；`cosmeticKey` 进一步只抹平引号与空白用于身份对接），不合并「元素附魔：冰 / 火」这类实质变种。

**卡壳与状态图标**：卡面图接口只对 `cardFace` 非空的实体返回牌面；状态牌 / 队伍状态 / 附加状态拿到的是 128×128 的对局状态图标（召唤物则有完整牌面）。所以无牌面条目渲染成与真牌面**同比例 420:720 的「卡壳」**——网格列宽与行高都不变，不会因为「这格没图」错位半格；壳自己用类型色（状态牌紫 / 队伍状态蓝 / 附加状态青 / 召唤物琥珀）＋顶部色条＋内嵌虚线框＋底部类型字标明这是对局实体，状态图标叠在壳中央、盖住壳的纹理（`onload` 淡入，`onerror` 撤掉图标只留 ◈）。数据源确实缺图的 4 个 id（`NO_ICON_IDS`：纵阵武力统筹 / 飞云旗阵 / 愚人众伏兵 / 破碎之海）连请求都不发；名单只是省一次必然失败的请求，漏了也会被 `onerror` 兜住。真牌面请求失败（离线或数据源缺图）时由 `artFallback` 就地替换为「卡面未加载」。

## 资源与数据约定

- 所有外部地址、图片地址、存储键、元素元数据与图标入口集中在 `src/core/resources.ts`；业务模块只 import 常量。
- 构建期源码清单只在 `scripts/sources.mjs` 声明：`APP_ENTRY` 是 TypeScript 入口，`LEGACY_SOURCES` 是尚未迁移的旧脚本（每迁一个删一行），`ASSET_SOURCES` 是资源脚本。构建脚本与测试加载器都读这一处。
- 新增模块时：TS 模块直接 import，无需登记顺序；仍在 `LEGACY_SOURCES` 的旧脚本按数组顺序拼接，新增须追加到末尾。
- 七元素图标由官方矢量归一化而来：去掉硬编码宽高、填充色统一替换为 `currentColor`，界面按元素色着色，亮 / 暗上下文自动适配。
- 资源更新后统一调整 `deck-viewer.html` 里的 `?v=` 版本戳，强制浏览器重新拉取。

## 数据来源

- 卡牌数据：piovium 官方静态数据服务 `https://static-data.piovium.org/api/v5`，本地缓存 24 小时，失败时回退到内置快照。
- 规则与术语释义：theBowja/genshin-db 中文快照（`vendor/genshin-db-data`）。
- 拼音索引：`pinyin-pro` 构建期生成，运行时零依赖。
- 七元素矢量图标：`assets/原神元素图标-矢量`。
